# HTF research continuity, checkpoint and timeout recovery procedure

1. Read latest GitHub branch HEAD and last known working commit; read Drive canonical governance index, then the investor mandate. Do not assume a previous visible message was successfully delivered.
2. Verify local source hashes and run the full Python regression suite. Confirm any generated checkpoint's exact input hash, code commit, UTC correction profile, financial assumptions and declared completion status.
3. Do not rerun a long job if it has already completed correctly. Do not accept incomplete `.partial` files or terminal timestamps that suggest truncation.
4. Freeze each signed plan before experiments. Save local atomic outputs after each month, store result hashes, upload to authorized Drive folder and read back metadata; record artifact URL in experiment result receipt.
5. Preserve negative/positive results, source paths, and code changes. Do not overwrite a good branch; fail and reverse isolated development changes if tests regress.
6. Record two next options (repair current best candidate and an orthogonal alternative) so the next session cannot restart with R9-only failure audits.
7. Never represent a ChatGPT UI timeout as loss of all files; check actual container, GitHub and Drive state first.

Manual acceptance criteria: source whitelist confirmed; DST normalized and matched UTC coverage; after-cost equity path checked for $100/$200; losses/negative months retained; broker-specific result files separate; research uncertainty declared; portfolio-level scorecard measured; user approval not assumed.
