## 1. Mandate, scientific framing, and priority

Quantitative research will test **mechanisms** in these seven lenses; combine them into the four established organizational categories ENTRY, HOLD, EXIT, and PROFIT without mistaking overlapping categories for independently additive results.

| Priority diagnostic lens | Reproducible questions / metrics | Primary organizational category |
|---|---|---|
| ENTRY / ACTION | Causal signal time/direction, immediate adverse selection, entry offset, admitted vs missed opportunities, first-tick eligibility, spread-adjusted markouts and entry expectancy. | ENTRY |
| HOLD / PERSISTENCE | Hazard and survival of favorable excursions, renewed extrema, conditional continuation, giving a surviving trade sufficient causal opportunity, spread/carry cost of extra time. | HOLD |
| EXIT / HARVEST | Fixed-entry alternate exit chronology, gross-profit captured, MAE/MFE *diagnostics after outcome*, giveback, target/stop/trail attribution and runner harvesting. | EXIT |
| STRUCTURAL OWNERSHIP | Independent higher-timeframe regime ownership, structure transitions, time-resolved invalidation and directional consistency. Structural state is computed only from information known at the tick. | ENTRY / HOLD |
| FAILED IGNITION | Failed breaks, false acceptance, reversion and stopout timing, suppression versus proactive response to a causally observable failed start. | ENTRY / HOLD / EXIT |
| TAIL CONTAINMENT | Worst-case adverse excursion, gross-loss mass, stress spread, fat-tail exits, leverage/exposure, max drawdown and $100–$500 theoretical solvency. | EXIT / PROFIT |
| OPPORTUNITY QUALITY | Conditional expectation net of execution costs, false negatives, trade-count retention, state clustering and volume of meaningful opportunities. | ENTRY / PROFIT |

Preserve mechanisms independently established to work **within BETA**; use controlled ablation against the last owner-approved cumulative Beta EA once one exists. At this checkpoint **there is no approved BETA EA or proven BETA trading mechanism**: preserving infrastructure and historical source identity is not inheriting Alpha/Gamma code or results.

**Original R9 REAL** is a historical broker real-tick performance comparator. **R9 SYNTH** and **R9 OVERFIT** are *capacity, counterfactual/hindsight, and missing-component maps*. Generated-tick P&L and future-aware optimal paths are **not** causal trade inputs or evidence of live profitability. Treat correlation, teacher-derived labels, and teacher models as research diagnostics only; feature definitions for an executable candidate must be independently causal and frozen before validation.

## 6. Durable checkpoint / crash-recovery protocol

**Never rely on chat stream text as the only copy.** Every bounded unit is a transaction with a stable identity:

```
unit_id = BETA_<milestone>__<study>__<YYYY-MM>__<unit_index>
state = PLANNED | RUNNING | LOCAL_COMPLETE | DRIVE_PERSISTED | GITHUB_MANIFEST_COMMITTED | VERIFIED_DURABLE | BLOCKED
```

A unit is **VERIFIED_DURABLE** only after:
- Its deterministic inputs, data date/range, raw-data hashes, code revision, preregistered rule, cached feature manifest, prior chronological state, outputs and *full negative results* are written locally to a temporary file and atomically renamed after completion.
- Compact results are uploaded to Google Drive and the exact destination has been **read back**; include upload identity, byte count/hash where possible. Large tick source and trade-by-trade logs are **not duplicated**.
- Small machine-readable manifest and code/checkpoint state are committed to GitHub's `beta` branch with immutable revision ID, matching pointers and digest. Verify branch state after commit. Avoid partial Git overwrites/force pushes.
- For sequential financial replay, month/bounded-unit outputs include opening and closing cash/equity, open position and pending order state, indicator warmup, tick timestamp and tie-break cursor, and reproducible continuation state so independently replayed spans match a single chronological account.
- Update the running manifest `last_verified_durable_unit` and `first_incomplete_unit` **only after both surfaces are confirmed**; a failed/partial upload is not verified. Recovered sessions identify and check the last stable artifact rather than repeating successful computations.

Bounded unit size can be day/week/partition within month so the runtime stays manageable; each full **month** is the outer checkpoint, and `JAN_MAR`, `APR_JUN`, `JUL` are report/throughput groupings. Unit hash/status enables idempotence. For independent parameter sweeps, deduplicate by input+code+parameters hash. For cumulative system P&L, replay states strictly in sequence; independent screens may run concurrently but must never have their profits summed as independent accounts.

After stream failure or model interruption, open **BETA** master protocol then GitHub `beta/CURRENT_STATE.json`, Drive `BETA_RESEARCH`, and compact committed checkpoint manifests; verify provenance/source SHA and choose **first incomplete** unit. Resume it; never rerun an identically verified durable unit simply because streaming failed. Ordinary Chat is canonical. **Do not require or recommend Work mode** absent owner's explicit request.
