### Interpretation and limits

1. **Observed:** The two tester modes select substantially different microsecond/second-level triggers despite almost identical M1 geometry. The win-count gap is not explained by fewer REAL opportunities. The earlier lifecycle differences are consistent with REAL entries failing to find favorable near-term prices before stops; they do **not** prove entry is the only cause, because entry selection and downstream stop/trail execution interact.
2. **Platform explanation:** MetaQuotes states that `Every tick` builds an artificial path from M1 reference prices, usually with the minute's fixed spread, while `Every tick based on real ticks` uses recorded broker ticks with variable spreads. A MetaQuotes three-mode example explicitly reports divergence in entry/exit levels and skipped trades when intrabar tick ordering changes. MT5 also may correct broker tick sequences using M1 bar consistency; `99% real ticks` is not 100% identical raw-tick identity. Original vendor sources: https://www.metatrader5.com/en/terminal/help/algotrading/tick_generation ; https://www.mql5.com/en/docs/runtime/testing ; https://www.mql5.com/ru/articles/2612 .
3. **Causal uncertainty:** M1 geometry ≈ equal plus erratic REAL quotes is *compatible* with generated-tick smoothness being the dominant confounder; other explanations (broker quote spread/Ask triggers, intra-minute state machines, rearm cadence, stop execution and cost rounding) are jointly plausible. No controlled counterfactual has yet isolated their individual contributions. Do not announce a solved cause or recoverable $359k.

## II. Exact historical R9 entry code inspected (read-only; no code inheritance)

Original historical source branch: `carson/r9-tick-logger`, file `Experts/GoldMuwahahaMiner_R9_TickLogger.mq5`, GitHub blob SHA `5c7655cd3357f9126e8bffd97c34374dfb29f83e` and historical `#property version 1.92`. Source: https://github.com/AnhTranHarris/gold-MUWHAHA-miner/blob/carson/r9-tick-logger/Experts/GoldMuwahahaMiner_R9_TickLogger.mq5 . The MT5 historical reports identify the R9 TickLogger expert with `InpRunLabel=REAL` versus `SYNTH`. Checking all input values in both tester report headers against an identical executable hash is **still an explicit future forensic control**, not something this source-only pass proves.

**Entry trigger:** Each new minute fixes a buy level = first observed quote **midpoint + 0.15 price/oz**, and sell level = first observed **midpoint − 0.15** (`InpGapPips=30`, `InpHunterPipPrice=.01`). `ProcessEntries()` triggers a long when *current Ask* exceeds buy level, or a short when *current Bid* passes below sell level (source lines ~532–569). **Important mechanical implication:** spread widening can raise Ask/lower Bid across a fixed mid-anchored trigger even without equivalent midprice momentum. That makes a new entry *potentially* a quote-spread artifact. The R9 spread gate blocks spreads above `InpMaxSpreadPoints=25`, but a fast change **inside** the cap or a change in fixed SYNTH spread can still affect boundary-crossing identity. This specific mechanism is independently supported by the Chinese/Russian MQL5 Bid/Ask spread explainer: https://www.mql5.com/zh/articles/9804 ; https://www.mql5.com/ru/articles/9804 . **Measured impact on R9 losses not yet isolated.**

**Directional gate:** Original R9 requires a *completed seconds-bucket* 10-second history, absolute quote displacement consistent with side ≥`0.15`, `|displacement| / summed absolute completed-S1 close changes` ≥`0.70`, 10 observed seconds' high–low range ≥`0.50`, and ≤`9` sign turns. The code stores only tick-containing completed seconds; it does **not** explicitly assert contiguous wall-clock second coverage or reject a stale time window (lines ~252–325). Thus 10 *observed* one-second buckets may span >10 elapsed seconds if feed gaps occur; generated and real quote sequences may populate those buckets differently. **This is a testable implementation-semantic concern, not a confirmed bug affecting R9's 149-day profit.**

**Broader gate:** `GetCompletedAtr` uses the **closed M5 ATR** (`CopyBuffer(...,1,1)`), 14 periods and session-dependent ATR thresholds, plus contemporaneous Bid/Ask spread. There is no clear evidence in this inspected code that this ATR uses future bars; do **not** allege ATR look-ahead. Qualifying signal allows a market order; stop geometry is about `0.30` price/oz plus broker stops; trailing activation around `0.10`, trail around `0.03`, max-hold 30 s. Existing Hold/Exit values are CONTROL settings, not yet the target of optimization.

**Repeated entry:** After an exit, the script can arm the *opposite side* within the same minute, up to three rearm cycles, conditional on new gate quality (lines ~542–593). A synthetic tick trajectory and a choppier real trajectory may accumulate very different post-exit orders and costs. Marker counts are *events*, not unique opportunities: historical REAL quality-reject log events 19.8m vs SYNTH 14.9m; historical rearm counts 230,245 REAL vs 219,342 SYNTH. Validate the rearm conditional effect by common-origin trade cohorts rather than assuming each marker is a distinct independent trade.

## III. Multi-round external source cross-reference → testable ENTRY repair hypotheses

### Round A: tick generation and short-horizon friction

- **MetaQuotes official (English)**: generated intraminute price and fixed M1 spread versus variable-spread real path; bid/ask order execution. https://www.metatrader5.com/en/terminal/help/algotrading/tick_generation — directly supports reviewing **source path and spread**, not a claim that a particular filter must win.
- **MetaQuotes Russian / Japanese same base article**: simple tick-sensitive EAs produce distinct entry/exit prices and skipped trades under generated vs real ticks. These two translations are **one original research article**, not two independent profitable validations. https://www.mql5.com/ru/articles/2612 ; https://www.mql5.com/ja/articles/2612 — directly supports retesting R9 bracket and completed S1 sequence.
- **MetaQuotes Chinese Bid/Ask explainer**: buys execute at Ask and exit at Bid, reverse for sells; real spread affects market orders. https://www.mql5.com/zh/articles/9804 — confirms why the exact R9 Ask-to-mid bracket must be decomposed.
- **FX market microstructure research**: spread, quote arrival, time-of-day and activity interact; hypothesis should be controlled using only observed broker quotes rather than idealized volume. Ito & Hashimoto (NBER 2004) https://www.nber.org/papers/w10856 ; McGroarty et al. (2006) https://www.sciencedirect.com/science/article/pii/S1044028306000251 — empirical *other FX markets*, not a Coinexx XAUUSD profit endorsement.

**Candidate family A — MID/BID-ASK TWO-PRICE CONFIRMATION (ENTRY QUALITY):** Keep R9's original minute-level candidate origin and exit controls fixed. For a long, preserve the R9 Ask crossing as a **candidate event**, but accept only if observed **midpoint** displacement and **Bid** movement confirm the same direction by a preregistered dynamic buffer (and mirror for short). Track changes in spread from minute anchor to crossing, quote gap and spread percentile. Reject quote-only cross and require a fresh, tick-observed move, not synthetic candle extrema. Study filters by matching R9 baseline candidate timestamps and acceptance cohorts, with trade-retention floor. Do not claim 'better' until after seven-month same-source test and broker-aware risk checks.

**Candidate family B — QUOTE-PATH PERSISTENCE AND FAILED IGNITION:** Compare last 250ms/1s/2s/5s/10s **as-of-tick** direction, midprice efficiency and immediate turn density, over *contiguous elapsed time*; require a second independent quote-confirmed impulse or shallow, successful hold beyond anchor, not simply one Ask/Bid threshold touch. Snapshot bar known-at times; source rows with an absent second must not be interpreted as consecutive seconds. Predict **positive 3/5/15s net bid/ask markouts** as post-hoc diagnostic labels, not into execution input. Test high-velocity admissions alongside percentage/winner count.

### Round B: trade-trigger chattering, acceptance/retest and volatility quality

- **Russian MetaQuotes false-trigger/chatter analysis** identifies excessive repeat entries inside a bar, tight targets and immediate re-entry as a system-level problem, with time/counter/amplitude debouncing as reconstructible controls. https://www.mql5.com/ru/articles/2110 — directly relevant to R9's same-minute opposite-side rearm path, not independent XAUUSD proof.
- **Chinese MQL5 opening-range implementation** freezes a known level and uses break→retest→second break with a causal OnTick state machine and ATR; proof-of-mechanism in a non-XAU example. https://www.mql5.com/zh/articles/18486 — possible *entry state* alternative, not evidence it beats R9.
- **Chinese MQL5 false-break momentum filter** proposes comparing short/long median-price momentum (Awesome Oscillator) to avoid momentumless breaks: https://www.mql5.com/zh/articles/16502 — reconstructible as completed-bar 5/34 midprice SMA delta, but must be ablated versus R9's existing efficiency gate to avoid redundant late filters.
- **Japanese MQL5 volatility breakout** adapts break requirements to completed ATR rather than a fixed touch: https://www.mql5.com/ja/articles/19459 — volatility direction is not assumed; additional complexity must show incremental utility, not just suppress trades.
- **Japanese TradingView open-source retest quality** uses completed confirmed swing reference, volatility-scaled breakout distance and retest zone: https://jp.tradingview.com/script/rFaVrkiK-Breakout-Retest-Signals-algotim/ . A separate TradingView Japanese page explicitly questions blanket ‘always retest’ claims and emphasizes expectancy **per originating break**, counting missed non-retests: https://jp.tradingview.com/scripts/retest/ . These are source ideas, **not** performance measured on the user's gold feed.
- **Korean MQL5 ATR education** provides a transparent reconstructed True Range / smoothed ATR volatility gating approach: https://www.mql5.com/ko/articles/10748 . It is an explanatory source, not proof that ATR-based breakout entry produces a high win count.
- **Reddit trader/developer discussion** on near-instant trailing and real-tick divergence reports spread/slippage/stop mechanics as possible confounders; this is practitioner anecdote, lower credibility than MetaQuotes' platform behavior. https://www.reddit.com/r/algotrading/comments/1l51t1l/ .

**Candidate family C — BRACKET ACCEPTANCE / RETEST WITH CONTROLLED MISSED-TRADE COST:** After an R9-origin bracket cross, inspect only *future ticks as they arrive* to distinguish shallow rejection/hold from immediate false break. Two causal branches: (1) fast 250ms–5s persistent acceptance without a deep retest; (2) time-limited retest-to-renewed-displacement. Use a *common parent bracket opportunity* as denominator, include breakouts that run without retesting (foregone wins), track extra adverse spread. If the retest filters most winners, fail the high-velocity/absolute-wins gate.

**Candidate family D — REARM-SPECIFIC FRESHNESS GATE:** Keep initial R9 first-entry logic identical; rearmed opposite-side entry must show **new** opposite-direction midprice displacement and an adequate stable quote context **since the actual prior exit**, beyond the stale minute-anchor crossing. Test rearm count, direction, cooldown, profitability and marginal winner count without artificially declaring rearm reduction to be a strategy winner. Compare no-rearm, original R9, and independent fresh-rearm controls on the same shared account.

**Candidate family E — SESSION COST/QUALITY ELIGIBILITY:** Vary only spread *relative to realistic expected excursion*, not raw points alone; require spread stability and completed M5 ATR state. Control for changes in opportunity volume, capital exposure and time of day. The original R9 logged gate-open share differs by only ~2.2 percentage points, so **spread gate alone cannot currently be assigned the entire 43.9-point historical win-rate gap**. It may nevertheless amplify Bid/Ask trigger asymmetry and stops.
