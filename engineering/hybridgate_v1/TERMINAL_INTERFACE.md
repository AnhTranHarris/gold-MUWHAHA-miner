# Stage 5H — terminal and broker interface contract (candidate, not native implementation)

Frozen V1 semantics are the source of truth. This contract is not authority to send any order. MT5 is first implementation; MT4 is a separate qualification, never a simplified intelligence substitute. The 12 accounts in the host core are simulated QA configurations, not 12 live books. The actual production account/risk profile must be explicitly selected and verified.

## Tick ingestion
- Treat OnTick/OnTimer as wake-ups, not as one callback per quote. MT5 `CopyTicks`/`CopyTicksRange` chronological retrieval, with overlap, full ordered tuple including flags and same-millisecond multiplicity; never deduplicate by timestamp or price alone. Persist last committed group, raw ordinal, multiplicity, source timezone convention and hash of overlap. If history is truncated, changed, unsynchronized, ambiguous or queue/capacity exceeded, block new entries and reconcile. Do not synthesize missing quotes. A timestamp group commits only after subsequent timestamp/history proof; never split ties at buffer boundaries. Catch-up observations can restore state, never replay stale trade actions against live market. Actual market orders cannot be guaranteed to fill at the research first quote after the decision; track decision, dispatch, server acceptance, fills and mark divergence. Measure delay introduced by group closure before any deployment. MT4 lacks the same documented ordered tick-history recovery contract; an independently certified acquisition method is required or MT4 remains unsupported.
- Normalize source UTC milliseconds and exact integer cents under the reference contract; validate symbol tick-size/grid and conversion at start and on spec changes. Never guess timezone or silently round a conflicting broker grid. Broker server time, UTC and NYSE calendar are distinct; explicit broker offset/DST mapping, fresh pinned calendar, holidays/shortened sessions, daily/weekly close and warm-up are required. Missing or stale calendar is fail closed. Preserve live monotonic dispatch clock separately from quote time.

## Execution contract
- Separate pure core intent from actual broker order. Maintain one selected actual account policy; reconcile account balance/equity, free margin, leverage, stopout, currency, contract size, symbol volume minimum/maximum/step, tick value, digits, stop/freeze level, execution/fill mode, allowed directions, sessions and commissions. Model 100% margin and 50% stopout are research assumptions, not substitute for `OrderCheck` and broker rules. Snapshot account type (netting/hedging), isolate magic/symbol/account identity; reject foreign or ambiguous positions. A model close is not a fill. Actual fill price/time/volume and commission/swap are broker facts; no invented profit or optimistic price assumption. Do not silently promote software exit floor to broker-side stop or alter trading intelligence.
- Before submit, durable intent record keyed by build, account, symbol, instance and sequence; write `SUBMIT_UNKNOWN` before outbound call. One outstanding action per position lifecycle; record requested volume/side and all request/order/deal identifiers. An ACK or successful OrderSend does not mean filled. `OnTradeTransaction` is a bounded notification queue, and events may arrive out of order; reconcile authoritative positions, active orders and history. Deduplicate by deal/order identity, not callback count. Cumulative filled quantity derived from unique confirmed deals; preserve partial fills, cancel remainder or close residual only under documented state and broker constraints. Never resubmit blindly after timeout/crash. Unknown outcome freezes new entries until reconciliation; if proof of absence is unavailable, operator intervention. This gives at-most-one attempted submission per durable intent, NOT guaranteed exactly-once broker execution. Close/reject/partial/timeout/requote handling must be separately certified.
- MT4 adapter uses ticket/order reconciliation against actual active/history records; no assumed MT5 transaction callback or position semantics. Confirm broker's supported tick timing and available history; no claim of MT4 equivalence yet.

## Runtime safety
- Startup: model + source + calendar + config digest, bounds, checkpoint envelope and journal committed prefix, fresh symbol/account contract, reconciliation, then warm-up. Any failed gate stays DISARMED. No trade sends in QC scripts. New entries disarmed by default. On disconnect, data gap, latency budget violation, queue overflow, corrupt state, clock loss or unclassified broker state: block new entries; preserve or reconcile existing exposure, execute only authorized protection/flatten policy where broker connectivity permits. Never report flatten as successful without broker confirmation. Terminal crash or connectivity loss can prevent any software stop. Emergency protection policy must be approved and native-tested separately.
- Save committed checkpoint and journal together, with strict version, checksum, generation, build/config digest, durable intent ledger. Host atomic rename/fsync is not proof of native file durability. Bound hot quote ring, pending queue, transaction mailbox and journal segment. Rotate journal only after new checkpoint validated and previous generation preserved. Watchdog measures monotonic queue delay, quote staleness, service time, model memory and transaction lag; limits are separate engineering config, not tuned to historical profit.

## Human-in-loop acceptance
Phase 6 uses a new GitHub branch and immutable base; compile isolated non-trading QC script, then integrated dry-run script, then trading adapter disabled. User provides compiler build, all diagnostics, terminal build, installation path, broker symbol contract and full logs. Never commit a claimed EX5 build from host C++ evidence.
