## Corrective implementation
- HG6CommitLink: broker ledger carries released intent sequence and minimum verified core generation. Core snapshot carries applied sequence. Normal release requires a matching resolved sequence and strictly newer verified core generation; startup and entry readiness cross-check both. Reapplying a resolved outcome already in the snapshot is skipped. A crash after order send without acknowledgement is UNKNOWN, never retried blindly. Broker rescue uses a separate persistent quarantine flag, rejects new entry and disallows normal restart. It is intentionally not silently merged into normal core state.
- HG6Broker: version 4 intent payload; reuse encoder workspace; durable local NOT_SENT outcome only when positively known no send occurred after persistence (expired budget, changed quote, changed exposure or lost permission). A crash before NOT_SENT persistence remains UNKNOWN. Requires flat/no-pending exposure to reconcile NOT_SENT. Actual broker order/deal evidence still authoritative for sent requests. Entry budget rechecked after core checkpoint and again immediately before OrderSend; no latency-based cancellation of emergency exit.
- HG6Storage: removed redundant second hash and full-payload decode/copy after the existing exact file readback; load still validates envelope hash, identity, slots and generations. Bounded two-generation storage is unchanged. HG6 main snapshot format v3; prior states intentionally incompatible, never delete to bypass ownership.
- EA: new save count/total/max/size, completed-pump max including periodic checkpoint, CopyTicks max. These are local wall-clock measurements, not actual terminal event-queue delay; incomplete/failed pumps not included in pump maximum. Entry suppression remains measured; new no-send guard can reduce dispatch frequency when overloaded, no strategy tuning.
