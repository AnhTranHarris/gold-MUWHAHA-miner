## 2. Data and numerical contract

Reference quote format: packed little-endian int64 timestamp ms, int32 bid cents, int32 ask cents. Preserve every quote including equal timestamps and identical quote values; stable ordinal is part of the identity. Bid/ask are executable sides, midpoint only when source calls for midpoint. Preserve integer-cent price conversion from original parser, original rounding/truncation and all feature units. A broker's _Point, tick size, price digits, contract size and deposit currency are separate properties. Initial native certification is USD account, XAUUSD with source-compatible cents and 100 ounces per lot; reject unsupported symbol spec rather than silently rescale model. Feature/mark units remain 0.01-lot equivalent (one ounce, cents); scale financial result by actual volume, never multiply model inputs by volume. Model research mark = direction*(current executable exit price - reference entry price)-2 cents. Real realized P&L uses broker deals and actual costs; do not mix modeled fee with actual twice.

All observers update from ordered ticks, including off-hours and while busy. Maintain separate candle states: V14 uses bid OHLC and prior completed bars across 250ms/S1/S5/S15/S30/M1/M5/M15/H1; FX01 uses midpoint S1/S5/S15/M1/M5/M15 with three completed bars plus current; do not substitute broker OHLC or share incompatible candle definitions. RX01 136 features include 250ms/1s/3s/8s/20s/60s/180s/900s trailing paths. Other observers carry their own directional-change, EMA, ATR, activity counters, bid/ask pressure, minute-phase and event clocks. Keep recursive ATR/EMA state and true initialization state; bounded rolling windows alone cannot reconstruct the exact recursive state. Determine required warmup from all observers and test cold start. A few hours of history is not proof of parity. On month reset, research mode starts fresh observers exactly as monthly scripts did; continuous native mode carries state across month boundaries unless a separate test demonstrates a safe reset policy. Month transition is not an automatic flat event. No retroactive decisions after catch-up.

Preserve source float32 staging, double accumulations, NaNs vs zeros, missing-value paths, log/exp/sqrt operations, objective link (binary sigmoid/multiclass ordering/regression), threshold inclusivity, ordering and tie decisions. No fast-math or compiler precision changes without comparison. No score or feature rounding to conceal March discrepancy. Model headers reveal no categorical splits in selected bank; verify numeric missing/default routing per tree anyway. Compare model outputs and decision margins at every threshold. Exact decisions required on identical inputs, except specifically documented historical archive drift; no tolerance-based override of trade decisions.

Three clocks: (1) source feature time (reference uses original source epoch), (2) validated canonical UTC/New York calendar for admissions/liquidation, (3) broker execution timestamps and monotonic elapsed local processing time. Do not silently reinterpret source model hour/day features as NY time. Establish real broker offset using observed server clock and trusted UTC, DST changes, reconnects; preserve replay offset=0 only as explicit historical assumption. Unknown/ambiguous time means no admission; risk exits continue.

## 4. Execution state: independent actual account domain

State machine: STARTUP -> RECOVERING/WARMUP -> FLAT_READY; FLAT_READY -> ENTRY_RESERVED -> ENTRY_PENDING -> OPEN -> EXIT_PENDING -> FLAT_COOLDOWN -> FLAT_READY. PAUSED/FAULT/OVERDUE are gating conditions; do not lose exposure state when setting them. Persist a write-ahead order intent before sending. One owned position/reservation/in-flight entry or exit at a time. Ownership via account/server/symbol/magic and position identifier, ticket and order/deal IDs. Initial deployment on isolated dedicated demo account, especially netting (foreign orders can merge into same symbol). Never close unrelated positions; unexpected/manual exposure on same symbol suspends entries and requires reconciliation.

Reference parity adapter: proposal t fills first quote strictly later than t (`searchsorted(...,'right')`); buy ask, sell bid. Historical account_kernel/clock_kernel rejects proposed fill ordinal <= prior exit ordinal. Admission checks modeled balance, mark including opening fee, margin; margin rejection consumes fill ordinal; 100% admission/50% stopout are historical assumptions. The account kernels process completed paths; no same-quote handoff and no queueing a blocked signal. Reproduce this exact behavior on reference replay, including the distinct behavior of proposals that share a timestamp. A proposal detected while an actual live position is open must not issue a new order; live adapter may lose opportunities reference would admit on a later quote. Certify this difference; never retroactively fill.

Live adapter: reconcile broker state, clock/permission, data readiness and signal freshness; get latest account balance/equity/free margin, symbol contract/filling/min/max/step/limit, actual leverage, session and terminal permissions. Compute ladder at dispatch from realized balance in integer cents; balance <=0 blocked; disabled 1 unit; enabled min(cap,1+floor(balance_cents/500000)); 1 unit=0.01 lot, max default 10, user override <=100. Reject unsupported size (do not round up to broker minimum). Use OrderCalcMargin and OrderCheck, not hard-coded 1:50 or 1:500. Volume and model configuration fixed for active trade. Send one uniquely recorded request. Synchronous/async success is not fill confirmation. Track request/order/deal/position associations; partial fills aggregate executed volume and VWAP, residual cancelled or reconciled; no new entry while remainder unresolved. Fill policy must be validated on broker; reject/timeout/unknown result does not justify duplicate blind retry. Reconcile actual deal/order/history before deciding further action.

Reference RX01 fill feature anchor is q[e], prior ordinal e-1 (last quote of proposal ms); if actual fill time/price differs, record both. For native actual-fill adapter candidate, use confirmed execution time, side and actual VWAP for hold age/economic mark, with as-of quote features from latest observed quote no later than fill time. Do not invent a quote or backdate an exit; if confirmation arrives late, reconstruct state from buffered observed ticks, evaluate safety now, dispatch at current market only. Partial fills and materially different price/time change the policy's effective inputs; test the actual-fill adapter separately against shadow parity and delay/partial-fill fixtures. Exact behavior on real broker fills is not yet approved. Never silently substitute simulated price for broker P&L. Additional conservative safety actions must be logged distinctly and explicitly human approved before activation.

## 6. Clock gate and event order

Clock default ON daily; weekly-only and disabled are preserved switches. Tokyo 09:00 opens corresponding NY trading date (previous ET evening 19:00 EST/20:00 EDT), normal NYSE 16:00 ET close, early close 13:00. In daily mode full NYSE holidays skipped. Freeze calendar coverage 2026–2028; no unknown-year assumptions. Weekly mode uses last eligible weekday of week; consult actual broker session separately. Gate on proposal AND dispatch/fill readiness; do not open on/after block time. At close-120s drain/cancel pending entry; at close-60s force close/cancel; at deadline verify actual flat. Disabled clock still requires valid clock and no overdue state per action(). Exit safety priority higher than any model signal. Timer and tick share an idempotent coordinator; timer is not guaranteed real-time. At time of closure late fill -> immediate liquidation. Weekends/holidays/unknown calendar remain blocked until reconciliation. Never ignore a forced exit because a model anticipates profits.

Per-event proposed native order (reference mode additionally runs the exact simulated fill and clock ordering):
1. Capture callback, sequence it; apply transaction updates idempotently and reconcile actual exposures; do not infer callback order equals server causal order.
2. Check current clock and safety; if overdue/flatten, latch and manage risk first. Even if no new ticks.
3. Recover all available ticks since persistent cursor using CopyTicks, not one SymbolInfoTick per notification. Include equal-ms boundary overlap plus stable occurrence multiplicity and full tick tuple. Detect history reorder/truncation and ambiguous cursor -> suspend entries. Do not dedupe identical values as though duplicate timestamps were errors. Use bounded backlog chunks, no unbounded event queue.
4. Update market observers in exact quote order and produce stage-specific shadow proposals. Do not place stale catch-up entries. For reference simultaneous states resolve source tie rules. For live clock and exit deadline check using current time before sending anything.
5. If owned position, update holding/renewal state on each observed eligible quote; merge intents, send only one close; while EXIT_PENDING, continue safety/reconciliation and no entry.
6. If flat-ready, consume new V26 proposal exactly once; apply clock, exposure, broker and margin checks; reserve capacity, persist intent, dispatch. No delayed queue of missed proposals.
7. Persist cursor/state/outstanding intent and ledger; record reject reason and execution latency. TradeTransaction callback minimal, reconcile from server history because events can arrive in arbitrary order and queue can overflow. If close confirmed, book actual realized account; wait later quote before next entry.

MT5 event responsibilities: OnInit load model/config hashes, symbol/permissions/timezone, checkpoint, reconcile and warmup; OnTick drain tick history; OnTimer perform clock, deadline, connection/reconciliation and bounded backlog checks; OnTradeTransaction record/reconcile actual trade outcomes; OnDeinit atomically checkpoint, never assume removal equals liquidation. Official references: https://www.mql5.com/en/docs/event_handlers/ontick, https://www.mql5.com/en/docs/series/copyticks, https://www.mql5.com/en/docs/event_handlers/ontimer, https://www.mql5.com/en/docs/event_handlers/ontradetransaction, https://www.mql5.com/en/docs/trading/ordersend, https://www.mql5.com/en/docs/trading/ordercalcmargin, https://www.mql5.com/en/docs/trading/ordercheck, https://www.mql5.com/en/book/automation/tester/tester_time, https://www.mql5.com/en/docs/onnx. Tick and timer events can be coalesced, transaction queue 1024 and arrivals not guaranteed ordered; do not block handler with monthwise inference or disk scans.

## 7. Restart/reconnect recovery contract

Persist versioned checkpoint with atomic two-generation write/rename or equivalent validated transactional storage, checksum, monotonic journal sequence and model/config hash. Scope account/server/symbol/magic; no secrets. Include full tick cursor (timestamp + occurrence + source ordinal, quote tuple/tail fingerprint), candle/ATR/EMA state, per-stage shadows/cooldown/role counts/last directions/pending anchors/history/marginal context, model priors and feature state, active position identity, confirmed entry/volume/VWAP, exit due, trailing floors, peak/trough ages, last event, risk accumulators, request/order/deal IDs, pending close/retry, clock/overdue and suspension state, last applied deal and account snapshot. Maintain bounded event journal and last-good checkpoint; serialize explicit field widths/version, no raw pointer state.

On startup/reconnect: disable entries; validate identity/version/hash; query actual positions/orders/deal history first; reconcile pending intent with broker, not local presumed status; restore last-good state; read missing ticks in order and restore market/holding state. No retrospective sends. If owned exposure exists, current clock/safety always wins, even if model missing or no checkpoint. If accurate state cannot be recovered, do not guess trailing floor or reset hold age; proposed fail-closed action is close owned exposure when permitted, log and require human review. No new trades until broker confirms flat, history cursor consistent, warmup ready, clock valid and operator mode allows. Unknown external position on netting -> quarantine, do not liquidate someone else's exposure. If market unavailable, stay overdue, retry safely, notify human; no promise of instant flat. Reloading an EA cannot reset realized balance, position age, past deals or ladder counters. Model/config changes permitted only in flat stopped state; restart with mismatch quarantined.
